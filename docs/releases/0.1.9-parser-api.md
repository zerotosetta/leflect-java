# 0.1.9 통합 파서 API와 단일 tgz 검증

POC1에서 통합 0.1.8 패키지가 JSP/TLD 함수를 공개하지 않고, 복사한 `.d.ts`에 배포본에 없는 `@leflect-java/schema` 참조가 남는 문제를 확인했습니다. 0.1.9에서는 파서 함수·요청한 타입을 명시적으로 공개하고, 도달 가능한 schema·하위 JSP 노드·EL AST 타입까지 선언을 번들링했습니다.

ESM은 명시적인 named export를 가진 `index.mjs`, CommonJS는 `index.js`, 타입은 자체 완결된 `index.d.ts`를 사용합니다. 선언에 외부 참조가 남거나 엄격한 타입 검사·원본 대비 공개 이름/값·타입 구분 검증에 실패하면 패키지 빌드를 중단합니다. 기존 `run`과 `analyzeWorkspace`도 유지합니다. [사용법과 입력 범위](../parser-api.md)는 tgz의 `PARSER_API.md`에도 포함됩니다.

검증 결과:

- `pnpm release:check`: 43개 파일, 테스트 **151개** 통과.
- 실제 tgz를 저장소 밖 새 디렉터리에 오프라인 설치: 런타임 패키지는 `leflect-java` 하나이며 외부 `@leflect-java/*`가 없습니다.
- 설치·진입점·가이드·CLI·타입 격리 검사 **21개**, ESM/CommonJS 런타임 계약 검사 **38개** 통과.
- 복사한 TypeScript 컴파일러만 개발 도구로 제공하고, Node16·NodeNext·CommonJS 해석 모드에서 `.cts`/`.mts`/`.ts` 소비자를 `strict: true`, `skipLibCheck: false`, `types: []`, `typeRoots: []`로 검사했습니다. 컴파일 입력 파일이 모두 격리된 디렉터리에 있음을 확인했습니다. Node16은 TypeScript 모듈 해석 모드이며 Node 16 런타임 시험을 뜻하지 않습니다.
- 중첩 JSP/EL AST, 속성, 한글·surrogate pair·CRLF의 UTF-16 inclusive 위치를 검증했습니다. import 시 CLI 출력·디렉터리 탐색·자식 프로세스가 없고, 문자열 파싱과 빈 registry 호출에서는 파일 IO도 없음을 확인했습니다. Node의 패키지 자체 JS/JSON 로딩은 허용했습니다.
- 명시한 TLD/JAR의 URI·핸들러·속성·원본 경로·중복 URI 진단을 검증했습니다. 빈 목록과 명시 파일은 주변 소스로 확장하지 않으며, 명시 디렉터리는 문서화된 범위에서 재귀 탐색합니다.
- 이전 0.1.8 tgz는 같은 소비자 검증에서 공개 진입점 누락으로 예상대로 거부됐습니다.
- 설치된 0.1.9의 `analyzeWorkspace`로 원본 `legacy-bank-java8`을 재분석했습니다. 동봉 worker가 실행됐고 Java 42개·JSP 계열 27개, 타입 43개·메서드 108개·호출 646곳, 그래프 미해결 0을 확인했습니다. 기존 117건·의미 검증 314개·JSP 구조·HTTP/TASK 등 회귀 묶음이 통과했습니다.
