# 0.1.8 배포 준비

상태: **버전 및 로컬 npm 패키지 준비 · npm 미게시**. 사용자 요청에 따라 현재 소스의 배포 준비 버전을 0.1.8로 맞췄습니다. npm publish·dist-tag 변경·배포 workflow 실행·v 태그 생성/push는 진행하지 않습니다.

## 버전과 포함 범위

루트 워크스페이스, 모듈 13개, private projection 앱의 package.json 15개를 0.1.8로 동기화했습니다. 앱과 루트는 private 상태를 유지합니다. Java worker의 자체 아티팩트 버전은 기존 0.1.0이며 새로 빌드한 JAR을 CLI 패키지에 포함합니다.

0.1.7 이후 반영한 Java/JSP 의존성 해석, 실행 요약, 함수 수집 상태 및 영향·사용 조회 개선과 검수 자료를 포함합니다. 최근 발견한 [보완 4개 유형과 범위·계약 3개 항목의 계획](../plans/2026-11-05-source-audit-revision-plan.md)은 구현 전 초안입니다. CMS·쿼리·리플렉션 연결 보류도 유지합니다.

## 로컬 준비 산출물

| 대상 | 준비 내용 | 경로 |
| --- | --- | --- |
| scoped npm 모듈 | @leflect-java/* 13종, 모두 0.1.8 | `.artifacts/release-0.1.8-npm/packages/` |
| 준비 manifest | 버전·태그·stage·tarball 목록; 게시 실행을 의미하지 않음 | `.artifacts/release-0.1.8-npm/release-manifest.json` |
| 단일 NPX CLI | leflect-java@0.1.8, 번들 및 worker JAR 포함 | `.artifacts/packages/leflect-java-0.1.8.tgz` |

모듈 manifest의 workspace 의존성은 실제 0.1.8 버전으로 치환했습니다. 최종 준비 경로에는 독립 실행파일 패키지를 포함하지 않습니다. 기본 matrix 생성은 Windows 호스트에서 첫 macOS ARM64 bytecode 생성 시 `spawn UNKNOWN`으로 실패해 준비 완료로 판정하지 않았습니다. 실패한 시도는 최종 npm 준비 manifest와 분리했습니다.

현재 CLI 패키징은 projection UI 앱을 함께 배포하지 않습니다. dashboard 사용에는 저장소 앱 또는 별도 앱 경로가 필요하며, 이번 버전 준비에서 이 기존 범위를 확장하지 않았습니다.

## 확인한 항목

- Java worker Maven clean package: 테스트 18개 통과
- TypeScript clean 이후 release:check: 테스트 38개 파일·114개 통과, 타입 검사·프로덕션 빌드 통과
- CLI help, custom-tag fixture 분석 및 FormTag 사용 조회 통과
- 로컬 NPX tarball 설치 후 별도 작업 디렉터리에서 help·init·analyze 통과; Java/Jasper JSP의 전체 AST 생성 확인
- 패키지 버전·내부 의존성·README/LICENSE·dist·worker JAR의 포함 내용과 해시 확인

산출물과 검증 로그는 Git에 포함하지 않고 로컬 `.artifacts/` 및 `analysis/release-0.1.8/`에 보관합니다. 버전 준비 변경을 main에 병합해도 npm 배포를 실행하지 않습니다. 이후 배포를 요청받으면 이 버전의 미게시 상태와 최종 패키지를 다시 확인한 뒤 진행해야 합니다.
